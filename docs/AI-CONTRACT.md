# Model adapter contract

POST `/api/analyze`: `{subject, image, referenceImage?, anchors?}`. The subject is freehand, house, car, cup, tree, or bicycle. Images are PNG data URLs. The sketch canvas is 800 by 600. Anchors are up to twelve sampled pen strokes, with up to eight [x,y] points each.

The frontend rasterizes the selected SVG reference to a 400x300 PNG. The backend sends separately labeled sketch and reference images, stroke samples, and a numbered list of known reference edges to the model.

The model returns `{summary, improvement, alignment:{edge,stroke,start,end}}`. Indices select a reference edge and two points from a sampled sketch stroke. It does not create drawing paths. The backend computes uniform scale, rotation and translation from that correspondence and applies the same transform to EVERY canonical reference path, preserving silhouette, proportions and details. The selected subject remains the learning goal. Any model-generated SVG is ignored.

Missing or invalid correspondences use automatic reference alignment based on the sketch's starting edge. This fallback is labeled separately from AI-selected alignment. Model correspondence selection remains approximate; preserving reference geometry does not guarantee the correct edge was selected.

For browser compatibility, the API returns `{source,guideSource,match,summary,steps:[{title,instruction,path}]}` with separate aligned reference components and an overall `improvement` explanation. The UI shows one component at a time, with Previous and Next part controls above the canvas. All components use the same transform; moving between parts does not make another model call. Model prose is rendered as text. Guides are excluded from exports; the original sketch is retained for the before image.

The backend limits input sizes and uses `AI_TIMEOUT_MS` (default 180 seconds). Browser recovery retains a reference guide if inference fails. Profiles and saves use browser localStorage and are not authenticated accounts.

Freehand uses a two-phase flow on `/api/analyze`:

- `{subject:"freehand", phase:"recognize", image, anchors}` asks for up to three distinct ranked object candidates, with confidence and visible reasons. The response is `{needsSelection:true, candidates, summary, suggestions}`. Recognition ignores the typed description; only the guide phase uses an explicitly chosen object. It crops the ink without stretching it and, for tilted elongated silhouettes, supplies a leveled view alongside the original orientation in the same model request. Candidates must be specific object names; fewer alternatives are allowed when only one interpretation is plausible. Recognition has no default object or animal-specific examples. The model also assesses the actual sketch for relevant practice suggestions, such as straighter edges, smoother curves, balanced proportions or connecting gaps.
- The browser keeps the original sketch visible while the user picks a candidate, enters an alternative name, or returns to drawing. It preserves the analyzed snapshot and cancels outdated requests when the subject is changed or the sketch is cleared.
- `{subject:"freehand", phase:"guide", selectedObject, image, anchors}` builds the simplified tracing reference for the explicitly chosen object. It does not re-guess or override that choice. It returns ordinary guide parts plus `object`, `chosen:true`, `simplifiedReference:true`, `improvement` and `suggestions`.

Every Freehand guide first searches Iconify's online Tabler and Lucide outline catalogs for the requested object, then downloads the selected drawing's SVG geometry as JSON. Search excludes filled, disabled and unrelated collection variants. If there is no usable source, the API asks the separate image-generation model for a simplified raster outline reference.

The backend accepts only supported outline primitives, normalizes relative paths and repeated commands into explicit absolute coordinates, converts circles/rectangles/lines to paths, and applies a single uniform scale and translation. All downloaded subpaths appear exactly once across up to three guide parts. For retrieved references, inference output cannot alter geometry. Source attribution includes the original drawing name, artist, source link and license.

The full reference panel and step overlay render these same source-derived paths. A canvas fitting transform keeps the complete guide in bounds. On a blank canvas, guide lookup and conversion require no model call. If there is an existing sketch, the model may provide improvement suggestions; feedback failure still returns the real online guide. Recognition remains a separate vision-model task. Demo mode can serve typed online references but cannot recognize sketches or generate missing references.

Freehand text input accepts object or scene descriptions up to 400 characters on an empty canvas, then uses the guide phase directly. Search covers the supported outline catalogs.

Generated fallback responses use `guideSource:"generated"`, `fitToPage:true`, and `reference:{generated:true,raster:true,cachedExample,url,width,height,paths,credits:[]}`. The backend uses a separate Hugging Face text-to-image model (`HF_IMAGE_MODEL`, `HF_IMAGE_PROVIDER`, `HF_IMAGE_TOKEN` or `HF_TOKEN`). Vision-model output never creates geometry. The image is decoded with sharp, flattened onto white, resized to at most 720x540, thresholded and thinned into actual stroke centerlines. Those centerlines become simplified SVG paths; small filled dots are retained as small circular marks. No invented subject components or numeric model paths are accepted.

Generated images are limited to 10 MB and 16 million decoded pixels. Generation requests preschool diagrams with a large main object, at most two setting shapes, side views for vehicles, and a white-interior minimal monoline prompt and a separate negative prompt excluding shading, color and fills. Qwen Image uses 28 steps and guidance 4, and fal receives `image_size:{width:1024,height:768}`. Validation requires at least 80% white or near-white paper, at most 6% midtones away from contours and 0.5% colored pixels. Large solid fills, blank images and excessive path complexity are rejected. Small dots and anti-aliasing remain supported. Accepted images are thresholded to pure black and white for the reference preview, using the same threshold as tracing.

Only `OutlineQualityError` triggers another generation with a stricter simpler prompt, up to `IMAGE_MAX_ATTEMPTS` (default 2, capped at 2; 1 disables retries). Provider errors fail immediately. All attempts share one `IMAGE_TIMEOUT_MS` deadline. Only accepted references are cached; concurrent requests for the same description share generation. Returned PNG data URLs show the normalized source image. Guides approximate source strokes within the tracing resolution, rather than claiming mathematically identical raster geometry. The latest twelve accepted references are cached in memory. These checks assess traceability, not semantic correctness, and prompting does not guarantee a compliant output.

The old prepared bunny scene is no longer selected because it exceeds the beginner detail limit. Missing image credentials or provider failures use the reference recovery flow below; existing online references still work. Invalid user input is still rejected.

A shared placement function measures all guide parts together. New empty-canvas and raster guides are centered and scaled to fill a 720x520 drawing area inside the 800x600 canvas. Non-scaling stroke widths keep magnified guides legible. The same transform applies to every part, preserving position during navigation.

Command/Control+Z and Command/Control+Shift+Z reuse canvas undo/redo. Input fields, editable content, open dialogs and active inference retain their normal keyboard behavior. Tests mock network/model responses and verify source geometry, attribution, unmodified retrieved paths, image generation, raster-derived geometry, complete-guide fitting, and reference lookup independent of model availability.

Freehand finishes with a single completed-drawing preview, labeled YOUR DRAWING. It does not capture or display a before image or original-sketch cutout. Downloads contain just the completed PNG, and new Freehand sketchbook entries omit the before field while keeping the existing after field for compatibility. Preset subjects retain their before/after comparison.


POST `/api/coach`: `{subject,image,referenceImage?,target?,partInstruction?}` reviews unfinished drawings with the configured local vision model. `image` contains the current visible ink at 640x480; during guided practice it excludes the original hidden sketch and the SVG overlay. Optional reference data is the actual generated PNG or rasterized SVG. The target is the selected object and the instruction identifies the active guide part. Context strings and PNG data URLs are size-limited. Output is `{source:"local",suggestions:[string]}`, with at most two short, deduplicated tips. The model is asked to assess existing marks, respect intentional curves and treat missing details as expected during practice. This endpoint never generates or changes reference geometry and does not call Hugging Face.

`GET /api/config` exposes `liveCoaching:true` only when the local provider and model are configured. The browser debounces stroke completion for two seconds and spaces requests by at least fifteen seconds, allowing only one active coaching request. Replies for outdated drawings are discarded. Clearing, subject or guide-part changes, disabling coaching, opening the completion preview and hidden tabs abort active requests. The HTTP backend forwards disconnect cancellation to local inference. Coaching uses `LIVE_COACH_TIMEOUT_MS` (default 30 seconds, bounded to 1–60 seconds) and `max_tokens:160`; validation or availability failures leave drawing practice usable and retry after another edit. Suggestions are rendered as text in a separate live panel.


Reference recovery uses a bundled Lucide library containing 1,772 validated, normalized outline drawings, with its ISC/Feather MIT license text preserved. Search failure for a simple description resolves whole-word primary nouns and common aliases to those original paths before calling image generation. Descriptions with scene relations continue through image generation first, then fall back to the primary subject if needed. The API preserves the requested `object`, returns `guideSource:"fallback-reference"`, `reference:{fallback:true,matched,title,paths,width,height,notice,...sourceAttribution}`, and `fitToPage:true`. Notices explicitly describe omitted scene details. No matching noun means `matched:false` and a clearly labeled line-practice guide using existing stroke anchors or basic shapes; that fallback never claims to depict the requested object. Invalid retrieved/generated geometry takes the same recovery path.

Generated references must also have at most 35 paths and 420 SVG commands; detailed results get a simpler retry and then the bundled/practice fallback if they still fail. A plain vehicle on a road/street/highway uses intact licensed vehicle paths and two road lines without requesting extra scenery.

After exhausted `OutlineQualityError` retries, cleanup first thins the existing ink into single centerlines. Filled images that cannot be thinned use smoothing, Sobel gradients and nonmaximum suppression. Complete contours are simplified into at most 80 safe paths, rendered as pure black lines on white, and passed through the ordinary outline validator. A successful result has `reference.repaired:true`. Both its cleaned reference PNG and SVG guide derive from the same paths. Blank or unrecoverable images still fail conversion and activate the bundled/practice fallback in `/api/analyze`. Provider errors do not trigger additional paid generations. Recovery guarantees visible practice paths for a valid guide request handled by a working backend, not correct semantics for every prompt or uninterrupted network access.
